How the pipeline sets a risk tier

Two model calls per application, wrapped in code that owns the policy, the routing and the checks.

  1. Code

    Validates the row

    Reads “$1,200,000”, “35M” and mixed dates. Bad rows are reported, never fatal.

  2. Code

    Sets a rules floor

    Shell companies, nominee directors, PEPs and injected instructions set a minimum tier.

  3. AI

    Quotes the evidence

    Fills a fact checklist and lists each red flag with a verbatim quote.

  4. Code

    Applies the policy

    Final tier is the highest of rules, policy and model. Low confidence moves it up.

  5. Code

    Picks the queue

    A fixed map from the final tier chooses the compliance queue, never the model.

  6. AI

    Drafts the brief

    Client profile, risk note and owner-tagged next steps, written from the final tier.

  7. Code

    Checks the brief

    The first step must go to compliance. “Approved” or “cleared” is flagged.

  8. People

    Decides on the board

    One monday.com item per client, grouped by tier, waiting for a named reviewer.

AI can raise a tier, never clear one

Rules and policy set floors the model cannot go below. Every record waits for human review.

Every flag carries its quote

Quotes are checked against the application, and every tier change records its reason.

Application text is data

An instruction hidden in an application becomes a red flag, not a command.
